## Intent

**Problem:** Stories 18.1, 18.1.1, and 18.2 migrated all Go validation logic to ValidatingAdmissionPolicies, but the ~92 Go webhook files, their `main.go` registrations, and a 717-line test file remain. This dead code creates unnecessary TLS handshake overhead, confuses the audit picture, and masks the true validation source (VAPs).

**Approach:** Delete ~82 webhook files whose only remaining logic is a no-op `Default()` (Category 4). Gut ~9 webhook files to defaulter-only by removing `WithValidator`, validating markers, and `Validate*` methods (Categories 2+3). Clean RabbitMQ's retained `Handle` to remove only VAP-covered checks. Remove ~81 `SetupWebhookWithManager` calls from `main.go`. Delete the now-invalid `webhook_validate_update_test.go`. Bump `minKubeVersion` to `1.30.0` and OCP annotation to `v4.17`. Evaluate the UserpassAuthEngineUser defaulter for removal (redundant with CRD schema default).

## Boundaries & Constraints

**Always:**
- Preserve all `Default()` logic in Category 2+3 files (complex/simple defaulters)
- Preserve the RabbitMQ raw `Register` handler and its `validateUniquePath` logic
- Keep `GetTargetNamespace`, `getLoginNamespace`, `CleansePath`, `JoinNamespace` in `commons.go` (used by RabbitMQ)
- Keep `webhook_suite_test.go` (still needed for envtest webhook infrastructure)
- Keep `vap_enforcement_test.go` (VAP tests from 18.1/18.1.1/18.2)
- Run `make manifests generate fmt vet test` after all changes to verify

**Never:**
- Do not modify VAP manifests, CRD types, or controller code
- Do not remove helper functions from `commons.go` (`GetTargetNamespace`, `getLoginNamespace`, `CleansePath`, `JoinNamespace`, `ValidateCredentialSource`) — these are still used at runtime by RabbitMQ and retained defaulter types
- Do not delete `isValid()` methods on `_types.go` files — they are on the type structs, not in webhook files; leave as dead code for now

## Design Notes

**Gutting pattern for defaulter-only files (Category B):** Remove `WithValidator(r)` chain call from `SetupWebhookWithManager`, the `mutating=false` kubebuilder marker, `Validator[*T]` compile-time check, and all three `Validate*` methods. Keep `mutating=true` marker, `Defaulter[*T]` check, `Default()` body, and helpers.

**Category C files are left untouched.** Their no-op `Default()` is harmless; future optimization can gut them to validator-only. The priority is correctness — their CRD-specific validation has no VAP equivalent and must not be removed.

**VAP coverage verification methodology (Loop 1):** For each type with `isValid()`/`ValidateUpdate` logic beyond path/name/targetNs/credentialSource, checked whether a `config/vap/vco-validate-<type>.yaml` exists AND whether the VAP's CEL rules cover all the Go checks. Types with partial VAP coverage (e.g. PKISecretEngineConfig: VAP covers acme/cluster but not type/privateKeyType immutability) are conservatively retained.

**isValid() callers after cleanup:** Defined on type in `*_types.go`, not webhook files. After deletion, most become dead code; compiler won't complain about unused methods on types. Leave as-is.

**RabbitMQ:** Immutability/target-ns checks already removed in 18.1/18.1.1. Current `Handle()` only has `validateUniquePath`. No changes needed.

**UserpassAuthEngineUser:** `PasswordCredentials` is `RootCredentialConfig` with `+kubebuilder:default="password"` on `PasswordKey`. Webhook defaulter is redundant — delete as Category F.
