# Story 9.2: Upgrade test dependencies (ginkgo, gomega)

## Story

As an operator developer,
I want to upgrade Ginkgo from v2.27.4 to v2.32.0 and Gomega from v1.39.0 to v1.42.1,
So that we benefit from new test features (JSON reports, semantic version filtering, `--sleep-on-failure` debugging, `BeASlice`/`BeAnArray` matchers) and remain on supported versions.

## Acceptance Criteria

1. **Given** `go.mod` pins `github.com/onsi/ginkgo/v2 v2.27.4`, **When** it is updated to `v2.32.0` and `go mod tidy` is run, **Then** `go build ./...` succeeds with zero compilation errors.

2. **Given** `go.mod` pins `github.com/onsi/gomega v1.39.0`, **When** it is updated to `v1.42.1` and `go mod tidy` is run, **Then** `go build ./...` succeeds with zero compilation errors.

3. **Given** both upgrades are applied, **When** `make test` is run, **Then** all unit tests pass without any test code changes.

4. **Given** both upgrades are applied, **When** `make integration` is run, **Then** all integration tests pass without any test code changes.

## Dev Notes

### Upgrade Risk Assessment: VERY LOW

This is a **very low-risk, zero-friction** dependency upgrade. Both Ginkgo and Gomega follow strict backward compatibility within major versions. All changes between v2.27.4→v2.32.0 (Ginkgo) and v1.39.0→v1.42.1 (Gomega) are additive features and bug fixes — no breaking changes, no API removals.

**No code changes expected** — this is a `go.mod`/`go.sum` only change (plus `project-context.md` version update).

### Go Version Compatibility

Both target packages require `go 1.25.0` in their `go.mod`. This project uses Go 1.26 — requirement is satisfied.

### Notable New Features (Informational Only — no action needed)

**Ginkgo v2.27.4 → v2.32.0:**
- v2.28.0: Multi-component SemVer filtering (`ComponentSemVerConstraint`)
- v2.28.1: Auto-updated Go requirement to 1.24
- v2.32.0: `--sleep-on-failure` flag (pause at first failure for debugging), `-fd` flag (RSpec-style documentation output)

**Gomega v1.39.0 → v1.42.1:**
- v1.40.0: New release strategy — `master-lite` branch strips tests to reduce indirect dep bloat
- v1.41.0: `BeASlice()` and `BeAnArray()` matchers; pointer cycle detection in object formatting
- v1.42.0/v1.42.1: Plugin metadata, dependency bumps

None of these require any changes to existing test code. They are purely additive.

### Transitive Dependency Changes

Expected `go.mod` changes after running `go get` + `go mod tidy`:

| Category | Expected Impact |
|---|---|
| `golang.org/x/net` | May bump to a newer patch (already above minimum) |
| `golang.org/x/tools` | May bump (ginkgo CLI dependency) |
| `google.golang.org/protobuf` | May bump (gomega dependency) |
| Other indirect deps | Minor patch bumps only |

**Gomega v1.40.0+ release strategy note:** Starting from v1.40.0, Gomega strips test dependencies from the published module. This means upgrading gomega will **remove** some indirect dependencies from your `go.mod` that were previously pulled in through gomega's own test suite. This is a desirable outcome — it reduces `go.mod` bloat.

### Anti-Pattern Prevention

- **DO NOT** upgrade to pre-release or pseudo-versions. Use only tagged releases: ginkgo `v2.32.0`, gomega `v1.42.1`.
- **DO NOT** change any `*_test.go` source code as part of this upgrade. If `make test` fails after the dependency update, investigate the specific failure before making test changes — failure would indicate an unexpected compatibility break that needs story scope reassessment.
- **DO NOT** upgrade other direct dependencies (vault/api, hcl/v2, sprig/v3) — those are Stories 9.1 and 9.3.
- **DO NOT** run `go get -u` (upgrade all) — only upgrade ginkgo and gomega specifically.
- **DO NOT** adopt new test features (e.g., `BeASlice`) in existing tests — that would be a refactoring concern, not an upgrade requirement.

### Scope Boundary

**IN scope:** ginkgo v2.27.4 → v2.32.0, gomega v1.39.0 → v1.42.1, transitive dependency resolution, project-context.md version update.

**OUT of scope:**
- Adopting new matchers (`BeASlice`, `BeAnArray`) in existing tests
- Adding `--sleep-on-failure` or `--sem-ver-filter` to CI configuration
- Using ginkgo CLI directly (project uses `go test` which embeds the ginkgo runner)
- Upgrading the ginkgo CLI binary (not used in this project)
