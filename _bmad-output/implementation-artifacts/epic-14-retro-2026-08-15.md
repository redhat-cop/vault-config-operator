# Epic 14 Retrospective — High-Priority Missing Auth Methods (AppRole, AWS)

**Date:** 2026-08-15
**Epic:** 14 — High-Priority Missing Auth Methods (AppRole, AWS)
**Stories:** 14.1, 14.2

---

## Epic Summary

Both stories delivered in a single day with 100% completion. Story 14.1 (AppRoleAuthEngineRole) was a low-novelty implementation following established patterns — 1 CRD, 1 review cycle, 2 findings. Story 14.2 (AWS Auth Engine) was significantly more complex — 3 CRDs across two config endpoints and a role, 4 review iterations, 15+ findings. Neither story applied review fixes during the pipeline; all findings were recorded for follow-up. Key architectural decisions (no SecretID CRD, two AWS config CRDs, strict webhook validation) were validated during retrospective review and confirmed correct.

## What Went Well

1. **100% delivery velocity:** Both stories completed same day with no blockers — fastest epic in project history.
2. **All architectural decisions validated:** Six key decisions pressure-tested during retro; all held up under scrutiny.
3. **`durationToSeconds()` correctly adopted:** Epic 14 established the correct pattern for TTL normalization. Older types have a latent bug (raw strings vs Vault's integer-seconds read format) that 14.1 and 14.2 correctly avoid.
4. **Design decisions pre-resolved from Epic 13 retro:** SecretID scoping (#5), AWS config split (#6), and baseline verification (#7) were all completed before the epic started — zero design-time delays.
5. **No review cap hits:** 0/2 stories hit the 5-iteration cap (improvement over Epic 13's 75% rate). Story 14.2 had 4 iterations but resolved within cap.
6. **Pattern reuse strong:** AppRole followed KubernetesAuthEngineRole exactly. AWS followed GCPAuthEngine + AWSSecretEngine patterns.

## What Could Be Improved

1. **Review finding volume without fixes:** 14.2 accumulated 15+ findings across 4 iterations with zero fixes applied. All findings recorded as tech debt. This creates a growing backlog of accepted-but-unfixed issues.
2. **Phase B story file finalization still not implemented:** Story 14.1 file still shows `Status: in-progress` instead of `done`. Third consecutive epic with this gap.
3. **Commits went to `main` instead of epic branch:** The `bmad-epic-dev` workflow's `phase-logic.md` never created an epic branch — `{epic-branch}` was referenced but never defined. Required manual post-hoc fix (moved 10 commits to `epic-14` branch, reset `main`).
4. **TTL representation inconsistency introduced:** Epic 14 correctly uses `durationToSeconds()` but now the codebase has two patterns — older types emit raw strings/ints. Creates confusion for future developers.

## Key Decisions (Validated)

| # | Decision | Verdict | Rationale |
|---|----------|---------|-----------|
| 1 | No SecretID CRD | Correct | Ephemeral credentials don't fit declarative CRD model |
| 2 | Two AWS config CRDs (ClientConfig + IdentityConfig) | Correct | Preserves 1:1 VaultObject contract (one CR = one Vault path) |
| 3 | ClientConfig `secret_key` stripping | Correct as implemented | Code does `delete(desiredState, "secret_key")` — review finding was inaccurate |
| 4 | TTL fields use `durationToSeconds()` | Correct | Matches Vault read format; older types have latent drift bug |
| 5 | No integration tests for AWS CRDs | Accepted risk | Follows established cloud-provider rule ("Skip it") |
| 6 | Strict webhook validation (Option A) | Confirmed | Reject invalid field combinations at admission; relax only if Vault genuinely supports universally |
