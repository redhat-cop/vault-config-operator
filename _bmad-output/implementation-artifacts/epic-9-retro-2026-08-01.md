## Challenges

1. **RabbitMQ bug survived in production due to legacy test anti-pattern.** Story 9.0 exposed that the original RabbitMQ tests used the buggy `convertVhostsToJson()` to build expected values — literally testing `x == x`. Additionally, all test fixtures used single-entry configurations, so the multi-entry map reassignment bug was never exercised. The project rule ("never derive expected payloads from the code under test") existed since Epic 1 but was never retroactively enforced on pre-existing tests.

2. **Epic definitions drift from reality.** Story 9.4's premise was outdated — the epic described evaluating `pkg/errors` migration, but R1.3 had already removed it months earlier. Nobody refreshed the epic text when R1.3 completed. The story author caught it and pivoted gracefully, but this is a fragile safety net. Version targets were also stale (caught during Epic 8 retro) — 4th consecutive epic with drift.

3. **Helm in-place upgrade from Vault 1.x to 2.0 not supported.** Story 9.5's initial attempt to upgrade Vault via Helm chart upgrade with `--atomic` timed out and rolled back. Required clean uninstall + PVC deletion + fresh install. This is expected for integration test environments but not documented.

4. **Tracking artifacts drift from reality.** `deferred-work.md` still listed the webhook markers and logger fixes as open even though they were completed during the Epic 8 retro. Led to incorrect follow-through analysis until verified against source code during this retro.

5. **Pre-existing Makefile hygiene issue surfaced.** Story 9.5 hit a pre-existing bug where `LICENSE.txt` from the old Vault zip blocked re-extraction. Fixed in 9.5's review by switching to `unzip -o` and versioned binary path.

---

## Key Insights

1. **Dependency upgrade epics benefit from tight scoping, anti-pattern prevention sections, and batched execution.** Stories 9.1-9.3 followed identical patterns (go get + go mod tidy + go build + make test + make integration). This is a repeatable playbook for future dependency upgrade epics.

2. **Just-in-time version audits are now a 4x-validated formal requirement.** Every dependency upgrade epic since Epic 7.5 has had stale targets when audited. The practice works, but the underlying issue — planning artifacts drifting faster than they're updated — persists.

3. **Legacy test anti-patterns are silent until actively discovered.** The "no self-derived expectations" rule was effective for all new code, but pre-existing tests written before the rule were never swept. The RabbitMQ bug proves these silent violations can hide real production bugs.

4. **"Evaluate and decide" stories should have their premises re-verified at story creation time.** Story 9.4's success despite the stale premise was due to the story author's diligence, not the process. Building premise verification into the story creation workflow would make this systemic.

5. **Anti-pattern prevention sections in stories are a proven scope management tool.** Every Epic 9 story had explicit "DO NOT" lists. Zero scope creep incidents. Continue in all future stories.
