# Epic 11 Retrospective — High-Priority Missing Secret Engines (AWS, Transit, SSH)

**Date:** 2026-08-08
**Facilitator:** Amelia (Developer)
**Participants:** Alice (Product Owner), Charlie (Senior Dev), Dana (QA Engineer), Rspazzol (Project Lead)

## Epic Summary

Epic 11 delivered three new secret engine types — AWS, Transit, and SSH — with full CRD support (types, controllers, webhooks, unit tests, integration tests, and test fixtures). This was the first epic to add entirely new Vault-facing CRD types to the operator, unlike prior epics which upgraded dependencies or refactored existing code.

**Stories completed:**
- 11.1: AWS Secret Engine Config and Role CRDs
- 11.2: Transit Secret Engine Config and Key CRDs
- 11.3: SSH Secret Engine Config and Role CRDs

**Review rounds:** 18 total (R1–R9 across AWS, R1–R7 across Transit, R1–R8 across SSH)
**Findings uncovered:** ~30 substantive issues across all stories

## What Went Well

### Parallel story execution
All three stories were developed concurrently using git worktrees, with independent Kind clusters for integration testing. This cut wall-clock time roughly 3x compared to sequential development.

### Adversarial code review depth
The multi-model review strategy (development on Opus 4.6, review on GPT 5.4) caught real bugs that would have reached production — including write-only field rotation failures (AWS `secret_key`), type mismatches in `IsEquivalentToDesiredState` (`json.Number` vs `int`), and nil-vs-empty-map drift.

### Established patterns scaled well
The existing operator framework (`ReconcileWithFunctions`, `VaultResource`, `toMap()`/`IsEquivalentToDesiredState()`, generic `DecodeInstance[T]`, YAML fixture loading) handled all three new engine types without framework changes — each story was purely additive.

### Integration test infrastructure
The isolation protocol (unique Kind cluster names and host ports per worktree) prevented cross-story interference during parallel development.

## What Didn't Go Well

### High review round count
18 review rounds across 3 stories is significantly more than prior epics. Root causes:
1. **New territory** — prior epics modified existing code; this was the first to create new CRD types from scratch, so there were no "prior art" files to copy exactly.
2. **Vault API idiosyncrasies** — each engine has unique write-only fields, response shapes, and deletion semantics that required iterative discovery.
3. **Type-system mismatches** — `json.Number` vs native Go types caused drift detection bugs that only surfaced during review, not during development or testing.

### Transit partial-create orphan scenario
The Transit key's dual-path API (POST to create, POST to configure) introduced a failure mode where key creation succeeds but config write fails. The compensating delete may itself fail because Vault creates keys with `deletion_allowed=false`. This required extensive design discussion and was accepted as a known limitation with best-effort rollback.

### Shared framework near-miss
During Transit development, a proposed change to `reconcile_skeleton.go` (the shared reconcile skeleton) would have altered finalizer timing for all 40+ reconcilers. This was caught and reverted, but only after implementation — not during spec review.

### CRD registration gap
New CRDs were generated by `make manifests` but not added to `config/crd/kustomization.yaml`, causing the Helm chart integration test to fail with crash-loops. This was a simple checklist miss that cost a full test cycle.

## Lessons Learned

1. **Write-only fields are a recurring pattern** — AWS `secret_key`, SSH CA `private_key`, and several existing types all share the same challenge. The "always-write" controller pattern and "delete from desired state" comparison pattern are now well-documented.

2. **Vault response types must be matched exactly** — `json.Number` is not optional; it's how Vault's Go client returns all numbers. This caused subtle drift bugs that passed unit tests (when tests used Go `int`) but would fail in production.

3. **Nil vs empty map matters for `reflect.DeepEqual`** — Vault returns `{}` for unset map fields, but Go zero-values produce `nil`. The `toAnyMap*` helpers must return empty maps, not nil.

4. **New CRD types need a registration checklist** — `make manifests` generates the YAML, but Helm chart inclusion requires manual `kustomization.yaml` updates.

5. **Shared framework changes have blast radius** — Story-scoped work should not modify shared reconciler behavior without explicit escalation.
