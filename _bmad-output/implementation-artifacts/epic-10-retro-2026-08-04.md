## Challenges

1. **Podman/Kind incompatibility blocked `make helmchart-test`.** Story 10.2 discovered that `kind load docker-image` requires the Docker daemon, which Podman doesn't provide. The failure was pre-existing (confirmed identical behavior on unmodified code) but was first surfaced when Story 10.2 tried to run helmchart-test with Helm 4. **Resolved during this retro** — added conditional logic to use `kind load image-archive` with Podman.

2. **GOTOOLCHAIN workaround needed for golangci-lint v2.** Upstream staticcheck is incompatible with Go 1.27rc2, requiring `GOTOOLCHAIN=go1.26.4` pinning in the `make lint` target. This is a known upstream issue that will auto-resolve when staticcheck releases a Go 1.27-compatible version. **No action needed** — monitoring for upstream fix.

3. **Story 10.0's import-path migration broke 107 integration test fixture paths.** The `internal/controller/` depth change meant `../test/` fixture references needed `../../test/`. This was caught in review but highlights the fragility of relative path references in Go test fixtures.

4. **Story 10.0a required two review cycles.** The initial submission missed 4 `patchesJson6902:` files in `config/` that also needed v5 syntax migration. The reviewer caught them, but the pattern suggests that Kustomize deprecation sweeps need an explicit discovery step (grep for all deprecated keywords) rather than relying on manual file enumeration.

5. **Story 10.5 uncovered a latent namespace-transformation bug.** `config/rbac/kustomization.yaml` had `service_account.yaml` commented out, which silently prevented kustomize from transforming `namespace: system` in role bindings. This pre-existing issue only surfaced when the metrics RBAC files were added. Fixed as part of the migration.

6. **Integration test environment shows Vault auth token staleness.** `make integration` showed 6 failures — all "permission denied" timeouts from Vault kubernetes auth. These are pre-existing (documented in Story 10.0's dev notes) and caused by stale auth tokens in long-running Kind clusters. Not an Epic 10 regression.

## Key Insights

1. **Tool upgrade epics benefit from strict ordering: layout → syntax → tools → architecture → validation.** Epic 10's story sequence (10.0 layout, 10.0a syntax, 10.1-10.4 tools, 10.5-10.6 architecture, 10.7 validation) ensured each change built on a stable foundation. Attempting the kube-rbac-proxy removal before the kustomize syntax migration would have created conflicts.

2. **Architecture changes (10.5, 10.6) are fundamentally different from version bumps.** The tool upgrade stories (10.1-10.4) followed a repeatable pattern (version variable + download + verify). The architecture stories required understanding component interactions end-to-end. Review findings concentrated in these stories (3 of 14 findings in 10.5-10.6).

3. **Deprecated-syntax discovery should be grep-driven, not file-enumeration-driven.** Story 10.0a's review caught missed files because the developer enumerated known files instead of grepping for deprecated keywords. Future migration stories should include a "grep for all deprecated patterns" step.

4. **The dual-model approach (Opus 4.6 dev / gpt-5.4-medium review) continues to work well.** Review model caught substantive issues in 7 of 9 stories. The cross-model review provides genuine independent verification rather than rubber-stamping.

5. **Pre-existing infrastructure issues surface during migration stories.** Both the Podman/Kind incompatibility (10.2) and the kustomize namespace-transformation bug (10.5) were latent issues that only appeared because the migration changed the code path. Migration epics are effective at flushing out hidden technical debt.
