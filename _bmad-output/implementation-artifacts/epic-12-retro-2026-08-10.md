# Epic 12 Retrospective — Medium-Priority Missing Secret Engines (Consul, GCP, LDAP/AD)

**Date:** 2026-08-10
**Epic:** 12 — Consul, GCP, and LDAP/AD Secret Engine CRDs
**Stories:** 12.1, 12.2, 12.3

## Epic Summary

All three stories delivered successfully. The Consul story (12.1) sailed through with a clean review. The GCP story (12.2) required 3 review iterations due to format-mismatch complexities (HCL/JSON bindings, token scope ordering). The LDAP story (12.3) implemented a full integration test with OpenLDAP deployed in the Kind cluster.

## What Went Well

1. **Epic 11 retro action items were all applied:** Shared framework protection, CRD registration checklist, spec.name immutability rule, and json.Number rule all held throughout Epic 12.
2. **Clean review for 12.1 (Consul):** Demonstrates that the patterns are well-established — routine CRD types pass review on first try.
3. **Git worktrees used for isolation:** All three stories were developed in dedicated worktrees, preventing cross-contamination.
4. **Integration test for LDAP:** Successfully deployed OpenLDAP in the Kind cluster and validated the full lifecycle (config, static-role, dynamic-role creation/update/deletion).
5. **`make manifests` properly handled:** Unlike Epic 11, all generated files were correctly produced and committed without global side-effects.

## What Could Be Improved

1. **Story file status not updated to "done":** Stories 12.2 and 12.3 had their story files left in "review"/"in-progress" state while sprint-status.yaml correctly showed "done." This is exactly the drift the new blocking gate prevents.
2. **Review findings marked open but code already fixed:** The normalizeBindingsForComparison, sortAnyStringSlice, and durationToSeconds fixes were all implemented in the code but the review checkboxes in story files weren't ticked. Creates confusion during retrospective.
3. **HCL bindings remain a graceful-fallback edge case:** If bindings are written in HCL format and the HCL parsing fails, the field is excluded from comparison entirely. This means HCL bindings changes won't propagate until manually reconciled. Acceptable trade-off for now.

## Key Decisions

- **PasswordKey default:** Leave the current webhook-based approach (GCP overrides "password" → "credentials") rather than refactoring the shared RootCredentialConfig struct. The global default affects too many CRDs to change safely.
- **Normalization in toMap():** Adopted as the standard approach for Vault format mismatches — convert CRD data to Vault's read format so IsEquivalentToDesiredState gets apples-to-apples comparison.
