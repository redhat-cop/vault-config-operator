# Epic 13 Retrospective — Lower-Priority Missing Secret Engines (Nomad, TOTP, MongoDB Atlas, Terraform Cloud)

**Date:** 2026-08-14
**Epic:** 13 — Nomad, TOTP, MongoDB Atlas, and Terraform Cloud Secret Engine CRDs
**Stories:** 13.0, 13.1, 13.2, 13.3, 13.4

---

## Epic Summary

All five stories delivered successfully. Story 13.0 (retroactive documentation for Epics 11–12) remediated DNFR5 doc debt cleanly. Of the four code stories, only 13.3 (MongoDB Atlas) passed review on the first iteration — the remaining three (Nomad, TOTP, Terraform Cloud) all hit the 5-iteration review cap and were accepted as-is with remaining open findings. The epic demonstrated strong pattern reuse from earlier epics but exposed story spec gaps around multi-mode validation and conditional field semantics. A systemic orchestrator workflow gap was discovered: story files were not finalized (Status field, Code Review Record) during Phase B merge, causing drift with sprint-status.yaml — the same class of issue flagged in the Epic 12 retrospective.

## What Went Well

1. **`toMap()` normalization rule fully adopted:** Zero drift from format mismatches across all four code stories. The Epic 12 action item produced lasting benefit — `durationToSeconds()`, `json.Number`, and Vault-read-format normalization were consistently applied.
2. **DNFR5 doc debt remediated (Story 13.0):** Documentation-only story executed cleanly, adding docs for all Epic 11 and 12 engines. Established a docs-first habit that carried forward — all Epic 13 code stories included documentation as an acceptance criterion.
3. **Pattern reuse drove MongoDB Atlas to first-try approval:** Story 13.3 followed the AWS secret engine config pattern line-for-line (dual-credential resolution, always-write controller, `sortAnyStringSlice` reuse). The reviewer found zero patches — proof that established patterns eliminate review churn.
4. **Parallel worktree execution worked flawlessly:** All 5 stories developed in parallel worktrees via `bmad-epic-dev` orchestrator. No cross-contamination, clean sequential merges.
5. **Nomad integration test with real service in Kind:** Story 13.1 deployed a Nomad agent in the Kind cluster and validated the full config/role lifecycle against a real Nomad backend. Gold standard for integration testing.
6. **5-iteration review cap protocol worked as designed:** Three stories hit the cap; each time the pipeline halted and presented open findings to the user for a decision. No force-merges, no lost findings.

## What Could Be Improved

1. **75% review cap-hit rate:** Stories 13.1, 13.2, and 13.4 all hit the 5-iteration cap. Review findings in later iterations were increasingly edge-case-oriented (whitespace-only references, legacy field values on updates, import-mode convergence gaps), but some caught genuine design issues (TOTP URL-import non-convergence, Terraform Cloud credentialType inference).
2. **Story specs lack validation matrices for multi-mode types:** TOTP (generate vs import mode), Terraform Cloud (organization vs team credential types) — both had conditional field sets where the spec defined individual field validations but not the interaction between modes. This gap is the primary driver of review iteration churn.
3. **Webhook validation combinatorial explosion:** Every code story had at least 2 review iterations spent on validation gaps — fields accepted in wrong modes, empty objects not rejected, update-time transitions not validated. The reviewers were correct; the specs were incomplete.
4. **Story file finalization missing from orchestrator workflow:** Phase B merge updated sprint-status.yaml but did not update individual story files' `Status:` field or populate Code Review Record sections. This caused exactly the drift the Epic 12 atomicity guard was supposed to prevent.
5. **Epic 12 process action items were documentation-only:** Action items #3 (atomicity guard) and #4 (consistency check) were marked "done" in sprint-status but were implemented as documentation rules, not as code-level enforcement in the orchestrator. They had no effect during Epic 13.

## Key Decisions

- **TOTP URL-import non-convergence accepted:** URL-based imports may not reach a stable desired state if embedded values differ from explicit spec fields. Documented as a known limitation rather than blocked.
- **Terraform Cloud TTL write format:** `durationToSeconds()` numeric seconds used in `toMap()` to match Vault read format, even though Vault docs show duration strings on write. Correct for drift detection.
- **All 5-iteration cap findings accepted as-is:** User reviewed open findings for stories 13.1, 13.2, and 13.4 and accepted them. No further iteration required. Findings are tracked in story file Code Review Records.
